# Implementation Sequence

## Phase A — shared visual primitives

Create reusable primitives for:

- analytical headline
- Reasoning Trail
- metric detail group
- focus state
- evidence boundary
- contextual next action

## Phase B — locked Dashboard

Rebuild visual composition according to Dashboard contract.

Do not merely recolor an old dashboard.

## Phase C — Investigation Workspace

Use one persistent workspace shell/state.

Implement stage-specific analytical bodies:

- History
- PIC
- Angle
- Creator × Account

Do not fragment them into disconnected dashboard pages.

## Phase D — responsive behavior

Apply responsive rules after desktop composition stabilizes.

## Phase E — QA

Run the visual acceptance checklist across all surfaces.

## Safety

Implementation should remain reversible.

Use dedicated branches and clean commit boundaries.
