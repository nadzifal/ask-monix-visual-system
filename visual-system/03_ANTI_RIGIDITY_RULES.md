# Anti-Rigidity Rules

The previous assembled prototype felt rigid even when its logic was correct.

The cause was not only layout. It was the accumulation of typography, lines, borders, surfaces, and repeated component patterns.

## Typography

Avoid an administrative/report feel.

Do not make every headline, number, and label equally bold.

Create rhythm:

- one strong analytical claim
- quieter supporting copy
- precise but calm metrics
- muted labels

## Lines

Too many lines make the interface feel like a spreadsheet/report.

Use separators only when they carry local meaning.

Prefer spacing over borders whenever possible.

## Cards

Too many cards flatten hierarchy.

If everything is a box, everything feels equally important.

Default to open canvas.

Use cards only for:

- focus
- interaction
- compact grouping
- state

## Radius

Avoid generic SaaS card language.

Radius should be restrained and consistent.

Large rounded containers should not dominate the page.

## Visual volume

Not every element should "speak."

The page needs:

- loud areas
- quiet areas
- supporting areas

If tabs, metrics, cards, headlines, and actions all compete, the product feels heavy and rigid.

## Key test

Ask:

> If I remove this border/card/line, does the hierarchy still work?

If yes, remove it.
