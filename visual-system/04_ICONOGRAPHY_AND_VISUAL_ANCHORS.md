# Iconography & Visual Anchors

Status: **LOCKED VISUAL REQUIREMENT**

Ask Monix must not become a text-only intelligence product.

The approved moodboard uses visual cues to make the product feel modern, readable, and immediate. Minimalism does **not** mean removing icons or reducing every state to text.

## Principle

> **Use icons intentionally, not minimally.**

Icons and other visual anchors should help users recognize structure, state, and action before reading every word.

## Functional icon roles

Use consistent line icons for:

- navigation
- search
- filter
- back / Reasoning Trail
- expand / collapse
- drill-down actions
- time/history
- people/PIC
- angle/content pattern
- creator/account execution
- operational states
- evidence / uncertainty where useful

## Style

- simple line icons
- clean geometry
- consistent stroke
- normally 16–20px
- ink / muted / semantic color according to meaning
- no glow
- no oversized circular icon containers by default
- no icon for every metric merely to decorate

## Visual anchors beyond icons

Glanceability may also use:

- semantic dots
- arrows
- micro-bars
- sparklines
- compact trend glyphs
- grouped shapes
- local tint
- small state markers

These are preferable to adding more explanatory prose.

## Dashboard requirement

The user should be able to perceive the current condition of the brand **before reading the supporting sentence**.

The top area should visually communicate:

- brand
- condition
- direction
- strongest evidence
- where to investigate next

Text explains the state. Visual anchors make it immediately recognizable.

## Investigation requirement

Each stage needs a distinct visual signature:

- History → time / movement cues
- PIC → people/decomposition cues
- Angle → Output → Hasil relationship cues
- Creator × Account → execution/account cues

Do not let all four stages become lists of text and percentages.

## Failure mode

If the user has to read most sentences before understanding what is happening, the screen is too text-based.

If the user can understand the state from icons alone, the screen is too symbolic.

The target is **visual recognition first, textual precision second**.
